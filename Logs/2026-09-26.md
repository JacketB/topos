# Отчет о разработке Topos GIS — 2026-09-26

## Построение непересекающихся маршрутов оповещения (VRP / Ray-Sweep Clustering & TSP)

### 1. Постановка задачи
- При оповещении личного состава и доставке предписаний требуется формировать кольцевые или радиальные маршруты обхода/объезда адресов из исходного пункта (штаб/база/пункт сбора).
- Пользователь имеет списки адресов (Excel/CSV), которые необходимо импортировать в программу, автоматически или вручную геокодировать (находить координаты населенных пунктов или указывать дома кликом на карте), после чего распределять адреса между заданным количеством посыльных (экипажей) с минимизацией километража и времени движения.
- **Критическое требование**: маршруты различных посыльных/экипажей не должны взаимно пересекаться (чистая территориальная кластеризация), а порядок обхода внутри каждого маршрута должен быть топологически оптимальным (решение задачи коммивояжера TSP).
- Дополнительно требуется выгрузка готовых маршрутных листов в структурированный файл Excel со сводной ведомостью и индивидуальными маршрутными карточками для каждого посыльного.

### 2. Реализованное решение

#### 2.1. Сервис и алгоритмический аппарат (`DispatchRoutesService`)
В `src/app/features/map-view/services/dispatch-routes.service.ts` реализован полный цикл обработки:
- **Парсинг Excel/CSV (`parseExcelFile`)**:
  - Гибкий поиск колонок (ФИО, населенный пункт, улица, дом, квартира, телефон, координаты, примечания).
  - Автоматическое распознавание географических координат при их наличии в таблице.
- **Генерация образца таблицы (`generateTemplateWorkbook`)**:
  - Создание типового файла Excel со светлой стилизацией и подсказками по заполнению.
- **Автоматическое геокодирование (`autoGeocodeBySettlements`)**:
  - Быстрый полнотекстовый поиск по встроенной базе населенных пунктов Беларуси (`belarus_places.json`).
  - Учет типов населенных пунктов (г., д., аг., п., г.п.) и района/области при неточных совпадениях.
- **Секторная кластеризация без пересечений (`clusterAddressesRaySweep`)**:
  - Расчет полярного угла $\theta = \operatorname{atan2}(dy, dx)$ каждой точки адреса относительно стартовой базы.
  - Поиск максимального углового зазора (angular gap) между соседними по азимуту точками для определения оптимального разреза плоскости.
  - Нарезка непересекающихся лучевых секторов (Ray Sweep Partitioning) с равномерным распределением точек между $K$ маршрутами.
- **Оптимизация обхода (TSP Nearest Neighbor + 2-Opt)**:
  - Формирование начального обхода методом ближайшего соседа.
  - Локальная оптимизация алгоритмом 2-Opt для устранения внутренних самопересечений маршрута.
- **Трассировка по дорожному графу**:
  - Интеграция с `MarchRouteService.calculateGraphRoute` (граф дорог Беларуси $A^*$): расчет реальной трассы с поворотами, точного километража и расчетного времени прибытия (ETA).
- **Экспорт маршрутных листов в Excel (`exportRoutesToExcelFile`)**:
  - Сводный лист с общей статистикой (число точек, общий километраж, время, распределение по посыльным).
  - Индивидуальные листы для каждого маршрута с таблицей адресов, номерами очередей, полями времени вручения и подписи.
- **Рендеринг на карте MapLibre**:
  - Векторные слои `dispatch-routes-lines`, `dispatch-routes-points`, `dispatch-routes-start` с цветовой дифференциацией маршрутов и нумерацией очередности посещения.

#### 2.2. Пользовательский интерфейс (`DispatchRoutesModalComponent`)
В `src/app/features/map-view/components/dispatch-routes-modal/`:
- Модальное окно в светлой палитре Topos GIS (переменные `--color-primary`, `--color-bg-app`, `--color-border`, `--color-text-main`).
- Вкладки управления:
  - **Адреса**: загрузка файла, ручное добавление, удаление, статус геокодирования и кнопка интерактивного указания точки кликом на карте.
  - **Параметры**: выбор стартовой точки (кликом или по координатам), количество маршрутов (посыльных), средняя скорость движения, время вручения на 1 адрес, тип маршрута (кольцевой возврат на базу или радиальный до последней точки), режим трассировки (по дорогам или напрямую).
  - **Маршруты**: аккордеон рассчитанных маршрутов с карточками точек, хронометражем, километражем и экспортом в Excel.
- Строгое соблюдение дизайн-кода: векторные SVG-иконки без использования эмодзи.

#### 2.3. Интеграция с картой и панелью инструментов
- В `map-toolbar.component.html` добавлена кнопка вызова «Маршруты оповещения» с горячей клавишей `⇧D` и бейджем количества активных адресов.
- В `map-view.ts` поддержаны клавиатурные сочетания `Shift+D` / `Shift+В` и закрытие по `Escape`.
- В `map-canvas.component.ts` реализован режим прицельного выбора координат на карте кликом мыши для стартовой базы или любого адреса.

### 3. Верификация

## Устранение замечаний по сохранению маршрутов, интерактивному выбору на карте и стилизации HUD

### 1. Проблема отображения диалогового окна сохранения маршрута
- **Первопричина**: в `ExcelStylerUtils.saveWorkbookWithDialog` присутствовала устаревшая проверка `(window as any).__TAURI_INTERNALS__ !== undefined`, которая в среде Tauri 2 возвращала `false`. В результате вызов системной команды Rust `choose_save_path` блокировался, происходил fallback на отсутствующий в WebView2 браузерный `showSaveFilePicker`, и файл пытался скачиваться скрытым кликом по тегу `<a>`, который в WebView2 подавляется без вызова диалогового окна.
- **Решение**:
  - Обновлена детекция рантайма через асинхронный импорт `isTauri` из `@tauri-apps/api/core` с дублированием параметров `defaultName`/`default_name` и `targetPath`/`target_path`. Системное диалоговое окно Windows «Сохранить как...» теперь гарантированно открывается при сохранении.
  - В сервис `DispatchRoutesService` добавлены методы `saveRoutesToGeoJsonFile` (экспорт трасс в GeoJSON через системный диалог) и `saveRoutesToTacticalMap` (перенос маршрутов и адресов в постоянные объекты оперативной обстановки на карте и в проект `.tps`).
  - В подвал модального окна добавлены кнопки «Экспорт ведомости (Excel)», «Экспорт трасс (GeoJSON)» и «Нанести на карту», а также баннер статуса сохранения.

### 2. Блокировка доступа к карте при выборе стартовой точки
- **Первопричина**: контейнер модального окна `.dispatch-modal-container` размером 92vw x 86vh оставался в DOM со свойством `pointer-events: auto`, перекрывая события мыши даже при полупрозрачном бэкдропе и блокируя клики по холсту MapLibre.
- **Решение**:
  - При активации режима указания точки (`pickingTarget() !== null`) бэкдроп и модальное окно полностью скрываются из DOM (`@if (!pickingTarget())`).
  - Пользователь получает 100% свободный доступ к карте для панорамирования, масштабирования и точного выбора точки.
  - Курсор карты переключается в прицельный `crosshair`.
  - По нажатию клавиши `Escape` выбор точки отменяется с мгновенным возвратом модального окна без его закрытия.

### 3. Стилизация плавающего попапа (HUD) выбора точки
- **Первопричина**: плавающий баннер использовал темную тему (`#0f172a`), что нарушало требование единой светлой палитры Topos GIS.
- **Решение**:
  - Баннер переверстан в строгом соответствии с дизайн-системой Topos GIS: белый фон `var(--color-bg-panel)`, граница `var(--color-border)`, мягкая тень, чистые векторные SVG-иконки, бейдж с наименованием выбираемого объекта («Стартовая точка» или адрес) и аккуратная кнопка «Отмена (Esc)».

## Устранение смещения адресов и белорусско-русская фонетическая нормализация (Слоним, Ефрасиньи Полоцкой 8)

### 1. Проблема
- При поиске адреса «Слоним, Ефрасиньи Полоцкой 8» точка на карте позиционировалась за городом в районе деревни Петралевичи вместо точного жилого дома в Слониме.

### 2. Первопричина
1. **Лингвистическое расхождение (Орфография OSM vs ввод пользователя)**:
   - В официальной OpenStreetMap базе Беларуси улица записана на белорусском языке: `вуліца Еўфрасінні Полацкай`.
   - Пользователь вводит русский вариант: `Ефрасиньи Полоцкой`.
   - В русском варианте отсутствует начальная буква «в» (`ефр` против `евфр`), а вместо белорусского аканья «Полацкай» используется русское «Полоцкой» (`о` против `а`).
2. **Ограничение стемминга**:
   - Предыдущий 4-буквенный стеммер сравнивал префиксы `ефра` с `евфр` и `поло` с `пола`, давая нулевой скор соответствия (score = 0).
3. **Некорректный Fallback**:
   - При нулевом скоре срабатывал запрос первых 5 попавшихся домов Слонима (`stmt_city_only LIMIT 5`), вычислявший центр по случайным северным постройкам города у границы с Петралевичами.

### 3. Реализованное решение
- **Фонетический стеммер в Rust бэкенде (`src-tauri/src/lib.rs`)**:
  - Внедрена функция `phonetic_stem`:
    - Нормализация аканья гласных: `о` -> `а` (приводит `полоцк` и `полацк` к единому `палацк`).
    - Унификация исторических корней: `евфр` -> `ефр` (приводит `евфрасинни` и `ефрасиньи` к `ефрасинни`).
    - Схлопывание удвоенных согласных (`нн` -> `н`, `сс` -> `с`).
  - При сопоставлении оценка совпадения дома 8 на `вуліца Еўфрасінні Полацкай` в Слониме выросла со score 0 до **score 40** (100% точное попадание в дом).
- **Ликвидация ложного fallback**:
  - Удален fallback `stmt_city_only`, исключив случайные точки на окраинах. При отсутствии точного дома адрес корректно центрируется на официальном центроиде города из реестра `belarus_places.json`.
- **Интерактивная ручная коррекция в 1 клик**:
  - Если адреса нет в OSM или требуется ювелирная привязка к калитке/подъезду, в таблице адресов предусмотрена кнопка «Указать на карте» (или клик по плашке координат). Модальное окно скрывается, кликом на карте ставится точка, и координаты мгновенно и навсегда сохраняются в `LocalAddressCacheService` (`localStorage`).

### 4. Верификация
- `cargo check`: 0 ошибок.
- `npx vitest run`: 107 из 107 тестов успешно пройдены.
- `npm run build`: Angular бандл скомпилирован успешно.

## Стрелки направления движения, пеший режим маршрутов и помаршрутное скрытие/изоляция

### 1. Стрелки направления движения по ходу следования (MapLibre Symbol Placement: Line)
- **Проблема**: Сплошные цветные линии маршрутов не давали визуального понимания направления обхода/объезда адресов (куда именно идти человеку от текущей точки).
- **Решение**:
  - В `DispatchRoutesService` сгенерировано векторное SDF-изображение шеврона стрелки (`dispatch-arrow`) размером 24x24 px и зарегистрировано в карте через `map.addImage('dispatch-arrow', imgData, { sdf: true })`.
  - Добавлен векторный слой `dispatch-routes-arrows` типа `symbol` с параметрами:
    - `'symbol-placement': 'line'` — стрелки автоматически позиционируются вдоль полилинии дороги.
    - `'symbol-spacing': 75` — шаг расстановки стрелок каждые 75 пикселей.
    - `'icon-rotation-alignment': 'map'` и `'icon-keep-upright': false` — строгая ориентация стрелки по ходу перемещения от старта к точке 1, 2, ..., N.
    - Белая контрастная заливка шеврона с окантовкой цвета маршрута (`'icon-halo-color': ['get', 'color']`), обеспечивающая отличную видимость на векторной карте, спутниковых снимках и топооснове.

### 2. Пеший режим передвижения и оптимизация дорожного графа
- **Первопричина автомобильного движения**:
  - Ранее в вызове `MarchRouteService.calculateGraphRoute` жестко передавался тип `columnType = 'wheel'` (автомобили) и дефолтная скорость 30 км/ч.
  - В графе дорог действовали ограничения одностороннего движения (`oneWay: true`), а приоритет отдавался скоростным шоссе (`motorway`, `primary`), запрещенным или неудобным для пешехода.
- **Решение**:
  - В `DispatchConfig` добавлен параметр `transportMode: 'foot' | 'car'` (по умолчанию `'foot'`).
  - Для пешего режима задана нормативная скорость 4.5 км/ч (настраиваемая от 1 до 120 км/ч с шагом 0.5).
  - В бэкенде Rust (`src-tauri/src/lib.rs`):

## Двуязычный семантический словарь улиц, 15-км пригородный поиск, пространственный барьер (Spatial Fence) и сглаживание трассы маршрутов

### 1. Проблемы по файлу `адреса.xlsx` (г. Слоним)
1. **Ненайденные улицы**:
   - `вуліца Чарняхоўскага` (Черняховского, Черняковского) — не находилась из-за гласной `е/а` после шипящей (`ч`) в белорусской орфографии (`вуліца Чарняхоўскага`).
   - `Чырвонаармейская вуліца` (Красноармейская) — не находилась из-за перевода корня («красный» -> «чырвоны»).
   - `вуліца Яршова` (Ершова) — не находилась из-за белорусского предударного яканья (`ер` -> `яр`).

2. **Ложное позиционирование (улет в РФ / деревню Стаи)**:
   - Адрес «Слоним, Первомайская д. 6, кв. 4» позиционировался в деревне Стаи на границе Смоленской области из-за отсутствия связки `первомай` $\leftrightarrow$ `першамай` и глобального fallback на случайную улицу в базе.
3. **Дефект геометрии маршрута к дому (V-образные шипы на $180^\circ$)**:
   - При следовании по улице маршрут резко сворачивал к дому и возвращался обратно на ту же дорогу, образуя острые некрасивые выступы с наложением встречных стрелок на одной колее.

### 2. Реализованное решение

#### 2.1. Двуязычный семантический и фонетический словарь в Rust (`src-tauri/src/lib.rs`)
- В функции `phonetic_stem`:
  - Добавлена нормализация гласных `е/а` после шипящих (`ч`, `ж`, `ш`, `щ`, `ц`), объединяющая `черн` и `чарн`.
  - Добавлена нормализация предударного белорусского яканья (`яр` -> `ер`), объединяющая `ершов` и `яршов`.
  - Нормализованы основы `евфр` -> `ефр`, `димитр` -> `дмитр` и схлопнуты удвоенные согласные.
- Реализована функция `get_street_stems` с семантическим словарем топонимов:
  - `красноармейск` / `красн` $\leftrightarrow$ `чирвонаармейск` / `чирвон`
  - `первомай` $\leftrightarrow$ `першамай`
  - `колхоз` $\leftrightarrow$ `калгас`
  - `чернях` / `черняк` $\leftrightarrow$ `чарнях` / `чарняк`
  - `ершов` $\leftrightarrow$ `яршов`
  - `советск` $\leftrightarrow$ `савецк`, `октябр` $\leftrightarrow$ `кастрычн`, `железнодорожн` $\leftrightarrow$ `чигуначн`, `молодежн` $\leftrightarrow$ `маладзежн`, `партизан`, `коссов` $\leftrightarrow$ `косав`.

#### 2.2. 15-км пространственный поиск в пригородах и жесткий Spatial Fence

## Устранение ошибок поиска переулков (Тавлая 34), ликвидация V-образных срезок и архитектура выделенных подходов к зданиям

### 1. Первопричина ошибок и дефектов
1. **Адрес «Тавлая 34» (улет в Жировичи)**:
   - В SQLite базе адрес находится в пригородном поселке Тушевичи, примыкающем к Слониму (2 км от центра): `(599449, 'Тушевичи', 'завулак Таўлая', '34', lat: 53.0664, lon: 25.3331)`. В самих Жировичах дома 34 нет.
   - В `src-tauri/src/lib.rs` в запросе `stmt_nearby_house` поиск шел по `WHERE house_normalized = ?1 AND lon BETWEEN ... AND lat BETWEEN ... LIMIT 40` БЕЗ фильтрации по названию улицы в SQL. В радиусе 15 км от Слонима 107 домов с номером 34. Из-за `LIMIT 40` запись Тушевичей (rowid 599449) не попадала в выборку. Срабатывал fallback на улицу с корнем `%тавл%`, где первые 10 записей принадлежали Жировичам, и центроид ставился в Жировичах.
2. **Адрес «Колхозная 31» (лес на границе Альбертина)**:
   - В OSM здание `Калгасная 31` (Цивинщина, Альбертин) имеет координаты `53.09333, 25.39488`. Дорога проходит в 30 м южнее, а само строение в картографических данных OSM действительно стоит на краю лесополосы. Для точного смещения к калитке работает кнопка «Указать на карте» с автокэшированием в `localStorage`.
3. **V-образные диагональные изломы через жилые массивы**:
   - Маршрут строился между домами напрямую через граф. Сегмент съезжал с дороги к дому (`Road -> House`), а следующий сегмент возвращался обратно (`House -> Road`).
   - Функция `smoothRouteSpikes` пыталась устранить тупиковый разворот, пропуская одну из дорожных точек. В результате трасса соединялась напрямую от дома к соседнему перекрестку по диагонали прямо через заборы и строения, а шевроны направления указывали путь через чужие участки.

### 2. Реализованное решение

#### 2.1. Фильтрация по корню улицы и ранжирование по расстоянию в Rust (`src-tauri/src/lib.rs`)
- В `resolve_addresses_batch`:
  - `stmt_nearby_house_with_street`: внедрен SQL-фильтр `AND street_normalized LIKE ?6` и сортировка по расстоянию до центра города `ORDER BY ((lon - ?7)*(lon - ?7) + (lat - ?8)*(lat - ?8)) ASC LIMIT 10`.
  - Запрос для стемма `тавл` теперь сразу возвращает `Тушевичи, завулак Таўлая, 34` (2.0 км от центра Слонима) с максимальным скором.
  - В `stmt_city_or_nearby_street` также добавлена сортировка по расстоянию до центра города (`ORDER BY dist_sq ASC`), гарантируя приоритет улиц в черте города и ближайших пригородах перед отдаленными деревнями.

#### 2.2. Архитектура чистой магистральной трассы (Trunk Route) в `DispatchRoutesService`
- Магистральная трасса посыльного формируется **СТРОГО ПО ДОРОЖНОЙ СЕТИ**:
  - Точки домов исключены из магистральной геометрии.
  - Трасса проходит от стартовой точки последовательно через дорожные точки остановки перед домами: `Start -> RoadStop_1 -> RoadStop_2 -> ... -> RoadStop_N -> Start`.
  - В магистрали ликвидированы развороты на $180^\circ$ и диагональные срезки через участки.
  - Стрелки направления (`dispatch-routes-arrows`) лежат исключительно на магистрали и плавно ведут посыльного по улицам.

#### 2.3. Выделенный слой подходов к зданиям (`dispatch-routes-approaches`)
- Для каждого адреса точка остановки на дороге соединяется с маркером дома отдельным отрезком: `[RoadStop_i, House_i]`.

  - Тонкая пунктирная линия (`line-dasharray: [2, 2]`, толщина 2.5px, прозрачность 0.85).

  - При скрытии маршрута («Глаз» / «Только этот») подходы скрываются синхронно с магистралью.
  - Подходы интегрированы в экспорт GeoJSON и тактическую карту.
